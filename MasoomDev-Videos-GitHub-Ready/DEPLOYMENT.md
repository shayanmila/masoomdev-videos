# MasoomDev Videos — Cloudflare Workers + D1 deployment

## Status and architecture
This is a **production migration candidate**, not a live deployment. The existing UI, browser IndexedDB cache, Google Drive upload, unlisted links, and recorder bridge are preserved. The Node.js in-memory sessions and private-data.json are replaced with D1. Refresh/access tokens are encrypted with AES-256-GCM before being saved to D1. Videos stay in each uploader's Google Drive, not D1 or Cloudflare R2. Worker streams the Google Drive response without buffering 100 MiB in Worker memory.

**Do not upload `.env`, `.env.example` with real secrets, private-data.json, or existing local OAuth credentials to GitHub.** The previous local OAuth tokens and shares are not migrated automatically; re-connect your Google account and re-upload/re-share or build a separately audited import tool. Old localhost sharing URLs cannot work publicly.

## Step 1: Create Cloudflare account and activate domain
1. Register/login at https://dash.cloudflare.com and choose Free.
2. Add **masoomdev.online** to Cloudflare as a zone. Cloudflare supplies two nameservers; update them at the domain registrar only after checking existing DNS records carefully. Preserve existing Vercel website A/CNAME/TXT/MX records. DNS changes may interrupt the existing site if misconfigured.
3. No hosting purchase is required for initial free-tier testing. Cloudflare Free has daily request/CPU and D1 limits. It is **not** guaranteed unlimited public 100 MiB streaming.

## Step 2: Prepare Windows PowerShell
```powershell
node -v
npm.cmd install
npx.cmd wrangler login
npx.cmd wrangler d1 create masoomdev-videos-db
```
Copy `database_id` from the create output into `wrangler.jsonc` replacing `REPLACE_WITH_YOUR_D1_DATABASE_ID`.

## Step 3: Create remote database tables
```powershell
npx.cmd wrangler d1 execute masoomdev-videos-db --remote --file=./schema.sql
```
Optional housekeeping (monthly, after launch):
```sql
DELETE FROM sessions WHERE expires < unixepoch()*1000;
DELETE FROM oauth_states WHERE expires < unixepoch()*1000;
DELETE FROM rate_limits WHERE expires < unixepoch()*1000;
```

## Step 4: Set production secrets
Create two secrets via CLI (it prompts securely):
```powershell
npx.cmd wrangler secret put GOOGLE_CLIENT_ID
npx.cmd wrangler secret put GOOGLE_CLIENT_SECRET
npx.cmd wrangler secret put ENCRYPTION_KEY
```
Use the existing Google OAuth **Web client** ID and client secret. For `ENCRYPTION_KEY` use a **fresh 64-character hexadecimal** key generated by:
```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```
Save this encryption key in a password manager; losing it makes stored refresh tokens unreadable. Do not put secrets into `wrangler.jsonc`, the website, the extension, or a public repository. `SESSION_SECRET` is no longer needed: session tokens are hashed and persisted in D1.

## Step 5: Google OAuth redirect
In Google Cloud Console > APIs & Services > Credentials > your Web OAuth client, add **Authorized redirect URI**:
```
https://videos.masoomdev.online/api/auth/callback
```
The consent screen must be configured for the required Drive scope and test users, or go through Google's verification/publication requirements before broad public use. Keep the existing localhost redirect for local testing if desired.

## Step 6: Deploy Worker
```powershell
npx.cmd wrangler deploy
```
Cloudflare will show a `*.workers.dev` URL. **Do not test Google login there yet**: APP_ORIGIN is set to `https://videos.masoomdev.online`, and the Google redirect must match that origin.

## Step 7: Attach custom domain
Cloudflare dashboard > Workers & Pages > `masoomdev-videos` > Settings > Domains & Routes > Add > Custom Domain > `videos.masoomdev.online`. Cloudflare manages the DNS record and TLS certificate. If an existing record uses this exact subdomain, inspect it before making changes. Do **not** alter `masoomdev.online` or the current Vercel website project.

## Step 8: Public smoke tests
1. Open https://videos.masoomdev.online and sign in with an authorized Google account.
2. Upload a small MP4/WebM and enable anyone-with-link.
3. Confirm share URL includes `?v=...&t=...` and opens in Incognito without login.
4. Confirm video plays without Drive preview wait and reload uses browser IndexedDB cache.
5. Test Screen Recorder extension: load unpacked `extension/` at chrome://extensions and use Upload to MasoomDev Videos.
6. Test share revocation by removing public sharing in Google Drive; a fresh browser should no longer download the video. **Existing cached copies remain in viewer browsers** until cleared/evicted; revocation cannot remotely erase them.
7. Test 100 MiB and >100 MiB uploads, browser restarts, logout/reconnect, and errors.

## Constraints / security notes
- Free Cloudflare Workers currently have a 10 ms CPU/request allowance and 100,000 requests/day; crypto + D1 queries may exceed CPU in some paths. Measure actual runtime before public launch.
- Cloudflare zone Free has a 100 **decimal** MB request body limit; upload goes directly from browser to Google Drive (not through the Worker), avoiding this limit. The browser cache application limit is 100 **MiB** (104,857,600 bytes).
- OAuth access tokens are supplied to the signed-in browser for direct Google Drive upload, as in the working local app. Use only HTTPS, short-lived tokens, and a trusted browser.
- The frontend downloads entire video to IndexedDB before local playback. It can appear instant on fast connections but isn't adaptive streaming.
- Sharing links are bearer capabilities. Do not post them publicly. Keep Google Drive anyone-with-link permission enabled for unauthenticated playback.
- A worker deployment requires a Cloudflare account; this package does not deploy or change your DNS automatically.
